## 大版本：先查兼容，再一处一处改

大版本经常有不兼容的改动。官方把「框架或主要依赖的大版本升级」算作复杂任务，建议拆开做。

**第一步，先查会碰到什么：**

<Copy id="du-compat" title="升级前查兼容" code={`查一下把 React 从 16 升到 18 会碰到什么问题。
我想要：
1. 找出代码里已经废弃的 React 写法
2. 列出所有用了生命周期方法的组件
3. 找出用了 string ref 或 findDOMNode 的地方
4. 查第三方库能不能配 React 18
5. 估一下要改多少
做好的样子：一份清单，每个问题写清在哪个文件。
做完给我看：这份清单，和哪些第三方库也得跟着升大版本。先只看不改。`} />

**第二步，照着清单改：**

<Copy id="du-major" title="处理不兼容的改动" code={`把 axios 从 0.x 升到 1.x，处理好不兼容的地方。
我想要：
1. 列出 axios 1.0 更新日志里所有不兼容的改动
2. 找出代码里所有用到 axios 的地方
3. 每一处：给我看改之前、改之后，说明为什么这样改
4. 每一类改动单独提交一次
做好的样子：所有测试通过。
做完给我看：提交列表，和每一处改动的说明。`} />

「每一类改动单独提交一次」：哪一步出了问题，退回那一步就行。

几个包要一起升时，比如 react、react-dom、react-router-dom，把当前版本和目标版本都列给它。让它先排好升级顺序，再动手。

## 升完，让它全面检查一遍

<Copy id="du-check" title="升级后检查" code={`依赖升完了，检查一遍整个项目。
我想要：

2. 确认测试覆盖率没有下降
3. 有类型检查就跑类型检查

## 每周自动查一次

把下面这句发进一个新对话，它会帮你建一个<Term k="自动化" />：

<Copy id="du-auto" title="每周依赖检查" code={`建一个叫「Dependency Checker」的自动化，每周一早上 8 点跑。
我想要它每次：
1. 扫描所有 package.json 和 requirements.txt
2. 查出过期的依赖
3. 写一份报告，按大版本、小版本、补丁分组列出可以升的包
4. 把报告发到 Slack 的 #engineering 频道
做好的样子：自动化建好了，而且开着。
做完给我看：这个自动化的名字、运行时间和每次要做的事。`} />

第 4 步要先接好 Slack。没接的话，把第 4 步删掉，报告就留在它每次开的那个对话里，在对话列表里找得到。自动化怎么管，看[完整教程第 6 步](/guide/6-automations/)。

## 卡住了？

<Q q="一升级，测试挂了一大片。">
退回去，一次只升一个大版本的包。先用上面的「升级前查兼容」列出问题，再一处一处改。
</Q>
<Q q="让 /codereview 审升级的 PR，它不肯通过，说版本太新。">
code-review 技能不会通过发布不到 7 天的第三方版本。等几天再审，或者自己判断要不要先合。
</Q>
<Q q="每周的报告没出现在 Slack 里。">
确认 Slack 机器人装进了工作区，而且被拉进了 #engineering 频道。机器人读不到它没加入的频道。
</Q>
