## 先打开一个文件夹

开对话之前，先点 `Open Workspace`，选一个文件夹。这个文件夹就是它的<Term k="工作区" />，它在这里面读写文件。

第一次用，新建一个空文件夹给它，叫 `counter`。后面几步都接着用它。用 Docker 的话，把它建在 `/projects` 下面。

## 照抄一个小任务

回到首页，开一个新<Term k="对话" />，发：

<Copy id="first" title="第一个任务" code={`我想要：在这个文件夹里新建一个 index.html，页面中间有一个按钮，每点一次，按钮下面的数字加 1。只用这一个文件，不装任何依赖。
做好是什么样子：用浏览器打开它，数字从 0 开始；点 3 次按钮，显示 3。
做完给我看：改了哪些文件；你做了哪些检查，每一项看到了什么；怎么在浏览器里打开它。`} />

这段话就是新手课里的<Term k="三段式交代" />：

**我想要什么 · 做好是什么样子 · 做完给我看什么**

1. **我想要什么。** 一个能计数的按钮，就一个文件，不装依赖。
2. **做好是什么样子。** 从 0 开始，点 3 次显示 3。它会照着这条去试。
3. **做完给我看什么。** 改了什么、查了什么、怎么打开。只让它报改了哪些文件，你就不知道它查过没有。

官方对好提示词的要求是三条：具体、说清在哪改、范围小。范围小，指一次只做一个功能，一般不超过 100 行代码。

## 真实项目里，再补两样

交代真实项目里的事，还是那三段，每段写得更具体，再补上线索和不能碰的地方：

- **我想要什么。** 「修好 `src/api/users.py` 第 45 行的 TypeError」，别写「修一下 bug」。
- **做好是什么样子。** 哪些测试要过，用户应该看到什么。
- **做完给我看什么。** 跑了哪些测试，结果是什么。
- **再补上线索。** 文件路径、行号、完整的报错信息、相关日志。
- **再补上不能碰的地方。** 比如「对外的接口不能变」「只改这一个文件」。

大事拆成几件小事，一件一件交代。

<mark><strong>判断不了「做完没有」的话，它也判断不了。</strong></mark>「让它好看点」「看看哪里不对」这种话，先自己想清楚要什么再发。

更多写法见[怎么交代，它才不跑偏](/howto/good-instructions/)，现成的提示词见[照抄就能用的提示词](/howto/recipes/)。

## 看着它干活

它干活的时候，聊天最下面会出现一组正在进行的步骤。标题写着它正在做什么，两步之间显示 `Thinking`。

做完一组，标题会变成一句总结，比如 `Ran a command` 或 `Read a file`。点开能看每一步的细节。

想让它停下，点输入框里的 `Stop`。之后发新消息，它可以接着干。

## 做完检查一遍

它做完会写一段回复。交回检查结果的回复，大概长这样：

<Reply code={`① 改了哪些文件：新建了 index.html，没有别的文件。

② 检查结果
   ✓ 打开页面，按钮下面显示 0
   ✓ 点了 3 次按钮，显示 3
   ✓ 文件夹里只有 index.html，没装依赖
   ? 没法确定：我只在一个浏览器里试过

③ 怎么打开：用浏览器打开 counter 文件夹里的 index.html`} />

- **①** 看它改的是不是只有你让它改的。
- **②最要紧。** 每一条写着它做了什么、看到了什么。只说「改好了」、不写查过什么，就追问一句「你是怎么确认的」。
- **③** 照着做，自己打开看一眼。

<Callout type="ok">
你应该在文件夹里看到一个新的 `index.html`。用浏览器打开，点按钮，数字会加 1。
</Callout>

真实项目里，做完多查几样：

- **看改了哪些文件。** 点对话标题栏里的信息按钮，打开概览面板。这里有工作区、Git 状态和改动。`Files` 标签能逐个看文件。
- **每处改动都看懂。** 有没有改到你没让它改的地方。
- **跑一遍。** 跑测试、构建一次，再自己手动试试。
- **查有没有写死的密码或 key。**

## 接着聊，还是开新对话

- **同一件事没做完**：接着在这个对话里说。
- **换一件事**：开一个新对话。每个对话有自己的历史和设置。
- **想换个思路试试**：在某条消息上点 `Branch from here`。它会从那里分出一个新对话，原来的不变。
- **想让它一直干到做完**：用 `/goal`。

`/goal` 会让它一轮一轮干下去，每轮由一个负责评判的模型检查做完没有，直到做完或到了轮数上限：

<Copy id="goal" title="示例：最多跑 3 轮" code="/goal --max 3 add unit tests for the parser and verify they pass" />

它会多花模型调用。发一条普通消息就能打断它。

<Callout type="tip" title="看一眼花了多少">
输入框里有一个用量条，显示这个对话占了模型多少记忆空间（有的模型不显示）。点开能看 <Term k="token" /> 用量。对话太长时，可以在这里选 `Compact context` 压缩前面的内容。
</Callout>

## 卡住了？

<Q q="消息旁边显示 Failed to send。">
<p>网络慢或正在重连时也会这样。等消息出现在对话里，这个提示会自己消失。真的一直没发出去，再点 <code>Retry</code>。</p>
</Q>
<Q q="开了新对话，它不记得上一次聊过什么。">
<p>每个对话是分开的。想让它每次都知道项目的规矩，写进 <Term k="AGENTS.md" />，见<a href="/guide/7-customize/">第 7 步</a>。</p>
</Q>
<Q q="想把这次对话存下来给别人看。">
<p>点对话标题旁边的 ⋮ 菜单，选 <strong>Export transcript</strong>，可以下载成 Markdown 或 HTML 文件。文件在你的浏览器里生成。</p>
</Q>
<Q q="哪些事适合交给它？">
<p>加一个函数、给现有代码写测试、修报错清楚的 bug、改配置、小的重构，都很合适。要求说不清、全靠审美、零容错的代码，先想清楚，或者一定要人来审。</p>
</Q>

对话的全部功能见官方的 [Conversations](https://docs.openhands.dev/openhands/usage/agent-canvas/conversations)。
